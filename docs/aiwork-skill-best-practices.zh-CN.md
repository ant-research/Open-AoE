# OpenAoE Skill 最佳实践：用对话找到、检查并下载数据

简体中文 | [English](aiwork-skill-best-practices.md) · [Expert 最佳实践](aiwork-expert-best-practices.zh-CN.md)

**从“我想找一批厨房炒菜数据”开始，得到可复查的样本清单、质检报告、图表和审阅视频。**

本文聚焦 `openaoe-data-ops` Skill。它负责 OpenAoE 数据检索、筛选、质检、可视化与下载；机器人动作转换和模型训练准备，请使用单独的 Expert 指南。

## 1. 在 AiWork 中怎样使用

### 从技能中心安装

1. 在 AiWork 左侧进入 **专家·技能**，切换到 **技能**，打开 **技能中心**。
2. 在 **集市** 中搜索 **`openaoe数据助手`**，选择对应技能并安装。
3. 选择保存数据和结果的项目目录，开始描述需求。该技能的包名为 `openaoe-data-ops`。

![AiWork 技能中心：在集市中搜索 openaoe数据助手](assets/aiwork/aiwork-skill-marketplace.png)

### 手动上传安装包

也可以直接下载仓库中的 [openaoe-data-ops.zip](../packages/aiwork/openaoe-data-ops.zip)，在技能中心点击 **添加技能**，通过上传入口选择该 ZIP 并完成安装。搜索不到技能时，使用这一方式即可。

仓库路径：`packages/aiwork/openaoe-data-ops.zip`。下载方式和安装包校验值见[安装包目录](../packages/aiwork/README.md)。保留包内预置索引及配套状态文件，首次使用先检查索引更新。

你负责说明**用途、筛选条件、下载范围和输出目录**，Skill 将这些要求落实为数据操作并返回文件。先描述任务，再查看 Skill 如何将需求转成筛选条件。

在 Python 环境中即可进行元数据检索、筛选与图表操作。手部网格审阅需准备 MANO 模型及渲染依赖，先渲染短窗口，再处理完整片段。机器人转换与模型训练的操作见 Expert 指南。

## 2. 一个完整案例：筛选厨房炒菜子集

下面以厨房炒菜子集为例，走完检索、筛选、质检、可视化、下载和审阅六步，并展示各阶段的交付物。

### 第一步：先问数据里有什么

```text
告诉我 OpenAoE 数据集当前索引包含多少样本，索引是什么版本。
列出场景、动作、时长、分辨率和机型分布。
如果索引过期，先更新；本步只处理元数据。
```

**你会得到：** 数据概览、分布统计、索引版本信息。先确认讨论的是哪个快照，再决定筛选条件。

**实践要点：** 复用预置索引，并通过增量更新获取最新数据；将版本信息与统计结果一起保存。

### 第二步：把“炒菜为主”变成可复查的条件

```text
帮我找厨房场景、时长 1–5 分钟、双手操作、1080p、
平均标注置信度不低于 0.9，且以炒菜动作为主的样本。
先解释“炒菜为主”对应的 verb、object、动作时长占比或排名规则，
展示每轮命中数和物体分布，再保存完整候选集。
最后用 seed=2026 随机抽 3 个样本供我验收。
```

**你会得到：** 筛选口径、完整候选集、抽样清单和样本 ID。

**实践要点：** `stir` 还可能表示搅汤或拌沙拉，可以结合锅具等物体条件继续收窄。结合动作持续时间与占比判断是否“炒菜为主”。先保存完整候选集，最后再限制数量和随机抽样。

### 第三步：分两层检查质量

```text
对筛选出的完整候选集做 L1 元数据质检。
后续要做 retarget，请抽 6 个样本做 L2 深检，样本不足则全部检查，
核对 hands 有效帧、相机轨迹、帧数和时序对齐。
给我一份可以交给同事的报告，注明哪些是全量结论、哪些来自抽样。
```

**L1** 检查时间范围、标注字段、相机参数等元数据；**L2** 实际读取手部和轨迹文件，检查数据有效性及同步。

![质量报告示例：L1 全量结果与 L2 抽样结果分开呈现](assets/aiwork/skill-quality-report.png)

*图：厨房子集质量报告，分别展示 L1 全量检查与 L2 抽样深检的结果。*

**你会得到：** `qc_report.md`、机器可读明细及异常样本清单。结合 `pred_valid` 有效帧覆盖率和视觉复核，判断样本质量。

### 第四步：用图表确认你选中了什么

```text
画出这个子集的场景分布、动词分布和场景×手别热力图，
再抽 12 张样本卡片拼图，方便我确认样本是否符合预期。
说明每张图的统计单位，以及一个样本能否计入多个类别。
```

*图：场景分布用于检查子集是否集中在目标环境。一个多标签样本可以计入多个类别。*

**你会得到：** 分布图、交叉图、卡片拼图和图集索引。图表回答“这批数据是什么样”，审阅视频回答“某条数据是否对齐”。

### 第五步：按用途下载，保留复现依据

```text
验收样本通过。下载选中 3 个样本的动作标注和手部数据，
并补齐下游 retarget 与审阅需要的相机轨迹、视频和匹配的相机参数。
逐文件校验 SHA-256，支持中断后继续下载。
保存筛选条件、seed、样本 ID、版本快照、文件校验值和署名说明。
```

![下载交付示例：样本清单、校验结果与 manifest](assets/aiwork/skill-download-manifest.png)

*图：3 个样本的标注与手部数据交付，包含文件清单、校验结果与 manifest。继续用于渲染时，再补齐视频、相机参数和轨迹。*

**你会得到：** 下载目录、`_openaoe_manifest.json`、`ATTRIBUTION.md`。保存筛选定义、样本 ID、版本快照和校验值，便于复查与复用。

### 第六步：渲染审阅视频，再决定是否使用

```text
把前面下载好的样本渲染成手部重建审阅视频。
先检查 MANO 和渲染环境，用一个短窗口确认画面与手部对齐，
再处理其余样本。提供视频索引，记录帧范围、抽帧间隔与渲染参数。
指出左右手、遮挡、漂移或相机运动异常的片段。
```

*图：AiWork 桌面会话中的视频交付列表，包含文件路径、渲染规模和内容说明。*

*图：Open-AoE 审阅视频，组合呈现第一视角、手部重建、动作标注与世界坐标视图。*

**你会得到：** 审阅视频和 `_gallery.md` 等索引。抽帧能节省时间，但可能跳过短暂异常；发现问题时回到原帧率检查关键区间。

## 3. 最后应留下哪些文件

| 交付物 | 用途 |
| --- | --- |
| 候选集与抽样 `subset.json` | 解释样本怎样选出、怎样抽取 |
| 索引与状态/版本记录 | 明确统计快照 |
| 质检报告与明细 | 区分全量检查、抽样深检及未检查项 |
| 分布图与样本卡片 | 了解场景、动作和样本差异 |
| 下载数据及 `_openaoe_manifest.json` | 核对来源与逐文件校验值 |
| `ATTRIBUTION.md` | 保留署名和组件许可说明 |
| 审阅视频与参数索引 | 人工检查对齐、手部重建及时间范围 |

## 4. 接下来交给谁

- **只做数据研究或质检：** 到这里即可交付样本和报告。
- **需要目标机器人的动作：** 将下载目录、质检报告、原始 manifest 和审阅视频交给人类数据转换专家。
- **已有模型目标：** 让训练专家对齐数据语义与配方，再开始训练。
